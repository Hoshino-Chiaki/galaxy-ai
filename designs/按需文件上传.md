# 按需文件上传

客户端版本：0.7.6，已更新本机安装版本。分类：任务系统；分类提示词已扩展为“先制定方案、一次列齐资料清单、分析验证后执行”，全文见 [任务系统分类提示词](任务系统分类提示词.md)。

## 使用流程

1. 用户先描述任务；确实缺少必要文件时，AI 调用 `task.request-upload`。
2. AI 必须填写中文 purpose，说明需要的文件、文件用途和收到后要做的事情。工具返回上传入口标识，聊天显示原生卡片。输入框没有常驻上传按钮。
3. 用户点击“选择文件”，系统弹出文件选择窗口。凭证和本地文件读取均在 Electron 主进程；页面不能传入任意本地路径。
4. 文件以数据流上传，卡片显示百分比和已传大小。达到 99% 后等待服务器确认，确认后才显示完成；支持取消。
5. 服务器确认大小和 SHA-256，返回 file_id、当前用户目录中的相对 path、文件名、用途和到期时间。
6. 客户端携带 upload_id 自动发起下一轮对话。服务器重新核实归属，把真实文件引用提供给 AI；原始正文不直接塞进聊天。HAR 使用 `task.har`，传入实际返回的 path 或 file_id。
7. 如果后续 AI 请求失败，保留已上传文件，可以“重试”或“继续处理”，无需重新上传。

文件卡片的用途文本来自服务器记录。内容只作为资料，不提升为系统指令；读到实际内容前，AI 不能声称已经解析完成。

## 隔离与空间

- 请求、上传、解析、删除都校验当前登录权限、用户、工作区及对话。仅聊天中已经成功保存的工具调用可以产生可用入口。
- 文件保存在现有私有工作目录下：用户和工作区的摘要目录 / uploads / 服务器分配的 UUID / payload。模型收到的是相对引用，不是跨用户的磁盘路径。
- `task.har` 的聊天调用接受上传工具返回的 path 或 file_id；path 是上传引用，先转换为标识再校验归属，不直接打开模型指定的路径。禁止传入绝对路径、其他相对路径、网址或身份。CLI 通过私有管道取得服务器选定的文件上下文，使用禁止跟随链接的文件描述符读取。
- 单入口单文件，有效 30 分钟；默认单文件上限 128 MB，AI 可按需设置 1—256 MB。无扩展名文件也可上传，实际格式由后续解析工具验证。
- 每人同时最多 3 个待上传入口，文件总占用上限 512 MB。接收前预留声明大小，避免并发绕过配额。服务每次最多接收 2 个文件流。
- 成功上传默认保留 24 小时。每 10 分钟清理到期文件；创建新入口时也清理。允许手动删除文件，删除对话同步删除其上传文件。
- 失败、中断或最终鉴权失败会清理临时文件并释放空间预留。服务重启后，遗留接收记录到期会清理。
- Nginx 仅对指定上传内容地址放宽到 256 MB，关闭请求缓冲，避免先在代理磁盘额外保存一份。其他接口保持原来的大小限制。

## 实现位置

- 通用工具：`galaxy-cli/src/galaxy_cli/tools/task/request_upload.py`、`har.py`。
- 服务端：`backend/xingxu/uploads.py`、`task_tools.py`，以及现有会话、鉴权、CLI 调度和 HTTP 路由。
- 客户端：`UploadRequestCard.tsx`、`electron/upload.cjs`、受信任的 IPC 通道和聊天自动续接。
- 上传元数据独立保存在 uploads 仓库，文件不进入公共附件目录。

本次不新增 Python 任意执行、Windmill 或任务队列。现有 HAR 解析可在上传后直接使用，其他文件的处理取决于后续已授权工具能力。
