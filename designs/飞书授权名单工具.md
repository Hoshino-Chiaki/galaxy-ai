# 飞书授权名单工具

工具名 `feishu.authorized-users`，命令 `galaxy-cli feishu authorized-users --input JSON`，属于飞书分类。默认输入 `{}`，等价于 `{"action":"scope"}`。

| action | 必填参数 | 输出与用途 |
| --- | --- | --- |
| scope（默认） | 无 | 当前应用获准访问的 user_ids、department_ids、group_ids，以及 has_more/page_token |
| user | user_id | 一个真实授权员工的资料，包括 API 实际返回的姓名、工号等 |
| users | department_id | 一个授权部门的直属用户列表，不递归包含下级部门 |
| departments | department_id | 子部门列表；可选 fetch_child=true 递归读取 |

除 user 外均支持可选 page_size（1—50，默认 50）和 page_token（必须用实际上一页游标）。部门 ID 使用 open_department_id，即 scope 返回的 od- 标识；根部门 0 只有应用实际获准访问时才可用。

返回完整官方业务 JSON，并增加 `coverage=application_authorized_scope`。scope 的 has_more=false 仅表示授权资源这一列表分页结束，不代表部门已展开，更不代表获得了全公司名单。返回 department_ids 时继续展开子部门并逐部门、逐页获取用户，按 user_id 去重。group_ids 不自动展开，应说明尚未覆盖的部分。

应用身份的授权范围接口不依赖个人 `contact:user:search`；关键词搜索不能替代全员枚举。API 的 user_ids 直接对应考勤 employee_type=employee_id。先用实时时间工具确定工作日，再取得名单，每批最多 50 人查询考勤。不使用猜测的员工 ID 探测角色。

## 调用权限与执行

沿用 `feishu:read` 和 `feishu:attendance:company:read`，默认管理员可用。服务器先核验当前登录者、企业应用绑定和公司权限，再执行固定 GET 接口；读取后及 CLI 返回后再次核验。只将获准的业务结果通过私有管道交给 Galaxy CLI，不向新工具传应用 token，不开放任意 URL、HTTP 方法、身份、token 或文件参数。普通员工不能借此获取应用管理员的名单范围。

源文件分别为 `galaxy-cli/src/galaxy_cli/tools/feishu/authorized_users.py` 和 `backend/xingxu/feishu/service.py` 中的 `directory_credentials`。当前工具不经过官方 CLI 的命令透传，而由服务器的固定接口适配器读取、Galaxy CLI 按已注册契约输出；模型仍只有 galaxy_cli 入口。

## 错误信息

原生 CLI 的结构化错误及授权名单接口的错误保留数值 upstream_code、具体说明，以及实际存在的 http_status、request_id。例：无效员工请求实际返回 `1220001 / userIds all invalid`，会输出 `feishu_api_1220001`；部门范围未授权的 `40004 / no dept authority error` 不再被压成 feishu_unknown。只输出选定诊断字段，隐藏访问凭证和 Authorization，不输出原始鉴权配置、请求头或完整 stderr。

这些错误不能单独证明用户是否为管理员，补个人关键词搜索权限也不能扩大应用的数据授权范围。

## 验证

后端相关回归 110 项、CLI 155 项及 45 个子测试通过，未修改的官方飞书二进制测试在隔离环境跳过。真实 Galaxy 登录会话经完整网关执行新名单工具，刻意使用 page_size=1 验证了两页游标读取，取得当前应用授权的 2 个员工 ID，再成功读取他人考勤和 2 人批量考勤。action=user 也实际成功，未要求个人关键词搜索授权。

根部门查询实际返回 `40004`，无效 ID 错误实际返回 `1220001`，均保留 upstream_code。普通员工调用新名单工具实际返回 permission_denied，未获取公司名单。当前应用范围只有 2 个明确用户、没有授权部门；没有把该范围称为全公司，也没有改动应用授权范围。

核验摘要（不包含凭证或真实考勤明细）在 `artifacts/feishu-directory-20261111.json`。服务端可复核脚本沿用 `backend/verify-feishu-company-live.py`，名单来源已从诊断专用 HTTP 调用改为新注册的 Galaxy CLI 工具。核验会话结束后退出，仅保留原有客户端会话。
