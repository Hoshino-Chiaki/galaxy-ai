# 工具分类提示词与店铺会话

已部署至云端，桌面版本 0.5.0。分类提示词入口：控制台 → AI → 工具提示词。分类来自实际注册工具，不需要在界面另行添加。管理员修改，按工作空间保存；只给有权使用相应分类工具的用户附加说明。空白分类不附加任何消息，不改变工具权限。全局提示词保持用户现有内容。

## 店铺范围

模型仍只能通过 galaxy_cli 网关调用工具。网关输入除 args 外支持可选 shops：`"all"` 表示当前连接账号全部授权店铺，`"current"` 表示当前默认店铺，字符串数组表示明确的店铺 ID 或名称。业务参数仍放在 CLI 命令的 --input JSON 内，不接受凭证、任意网址或用户身份注入。

Youzan 分类提示词已经配置：未指定店铺时由 AI 传 shops="all"；明确指定时只查询指定范围。省略 shops 的旧调用保持当前默认店铺，避免在程序中把所有查询强制改成全店铺。清空分类提示词即取消这条额外指导。

只读查询逐店执行，保留各接口完整业务 JSON，结果形如 `{shops:[{kdt_id,shop_name,data或error}],partial}`。单店失败不冒充零数据；全部失败时调用失败。分页仍按各接口独立处理，总部和分店结果可能重叠，不直接相加。

写入类操作在服务器强制拒绝 all 和多店铺范围，只允许单店；分类提示词同时要求用户明确目标店铺。分类提示词不能授予权限，服务端始终检查当前用户、登录状态和工具权限。

## 凭证保存

复用服务器已经保存的 SID。每家店铺通过 enter-shop 和固定 CRM 页面进入，使用独立 cookie 容器获取 CSRF 及配套业务 cookie；按工作空间、登录用户、连接账号、店铺隔离，加密保存在服务器现有 youzan.json 的 shop_sessions 内。客户端和模型只能看到状态，不能读取凭证。

有赞设置页面会准备各店凭证。实际发现：相同 SID 在有赞服务端还关联“当前店铺”，仅保存独立 CSRF 和 cookie 不足以固定数据范围。工具每次执行前都会重新进入目标店铺、更新该店凭证，再立即发起业务请求；不直接使用先前缓存去跨店查询。控制台提供“刷新全部店铺会话”。SID 换新后旧缓存失效，准备会话不会启动浏览器或运行旧滑块登录程序，也不改当前默认店铺。SID 本身失效仍需正常重新登录。

相同 SID 的业务工具和后台会话刷新共用运行锁，覆盖进入店铺至工具请求完成的全过程；不同 SID 可并发。相同用户另有凭证准备锁，不同用户独立存储；提交时校验连接版本及 SID，工具前后再次检查身份和会话，登出或授权变化时丢弃结果。
