## 调用契约

每个业务域一个独立 Python 工具，例如 `tools/feishu/sheets.py`。

`galaxy-cli feishu sheets --input '{"action":"help"}'` 列出本域操作，可用 keyword 搜索；`{"action":"help","command":"spreadsheets.get"}` 取得该操作的完整参数结构、必填项、权限及输出说明。先以实际目录为准，不猜测操作名。

执行业务：action 指定操作名，快捷命令的字段放 options（字段沿用官方原名），API 的路径/查询参数放 params、请求体放 data。可选 dry_run=true。输出保持官方完整 JSON。下载或导出的路径转换为账号工作目录相对路径，取得真实路径后可使用 file.publish 下载。

工具描述和域内 help 包含输入输出；没有把飞书工具说明写进全局提示词。

## 权限与文件

模型仍只有 galaxy_cli 入口。服务器和 Go 包装层都使用固定命令目录；不开放原始 api、auth、config、shell、文档脚本执行、本机应用开发/密钥管理，以及持续同步/监听等入口。123 个未接入命令及原因记录在 feishu_catalog.json 的 excluded 中。飞书项目 Meegle 是独立 CLI，本次未接入。

每个员工独立保存授权。业务写入检查 feishu:write，读取检查 feishu:read，并继续受飞书本人的实际权限限制。当前管理员与员工角色均可在各自授权范围内读写，不能使用管理员个人 token 作为回退。写操作按用户明确请求执行，发送结果不确定时先回读；停止等待不能撤销已完成的写入。

App ID/App Secret 和已有授权不因本次扩展重置。连接时统一申请覆盖全部已接入用户能力的权限，不按业务域让员工选择。设备授权没有上一版所套用的 50 项分组要求；原始候选 252 项超出平台请求数量限制，去掉同一 API 的互相替代权限后，192 项即可覆盖当前用户身份操作，已验证单次设备授权请求被飞书接受。所有返回的真实授权按员工加密保存，旧版本凭证继续兼容使用；调用时自动选择含所需权限的有效 token，并独立刷新。所有 token 必须绑定同一个飞书 open_id 和 tenant_key，禁止混合不同团队/账号。

控制台仅保留连接／补全授权入口，没有范围选择器。管理员可复制一次性权限导入 JSON，在飞书后台开通用户身份权限并发布；员工完成飞书本人确认。服务器自动选择申请范围，不能替代飞书批准尚未开通或本人未同意的权限。

Go FileIO provider 使用 os.Root，文件读写只在服务器选定的账号工作目录。拒绝越界、软链接、特殊文件，保存采用临时文件加原子替换。未恢复任何本地后端、业务 CLI 服务或浏览器运行时。

## 生成与验证

`backend/feishu/cli/catalog-export/main.go` 在服务器从官方源码导出公开快捷命令元数据；`generate-catalog.py` 将其与官方 Catalog Snapshot 合并，产生 galaxy_cli/feishu_catalog.json、Go 命令清单以及独立域模块。CLI 版本和元数据固定同一 commit，不能只更新其中一项。

验证分为目录与 schema、参数注入、读写权限、员工隔离、分组授权保留/刷新、不同飞书身份混入拒绝、Go 文件目录隔离、官方 CLI 预览、实际已授权只读链路和 Windows 界面。新增写入能力不会对用户的真实飞书消息、文档、表格做批量测试；待用户授予对应范围并指定操作后再执行真实业务写入。

## 本次验证结果

后端 238 项通过，CLI 127 项及 55 个子测试通过，Go 工作目录隔离 2 项通过，669 个命令入口全部通过官方 CLI 路径识别检查。两项旧固定登录测试因该运行时已退役未运行。后续审计操作名和部分授权状态的小改动另通过针对性回归。

服务器已部署并通过健康检查；原 App ID、密钥、个人授权数据保持原样。Windows 10 已验证 0.6.0 覆盖升级到 0.7.0、保留登录、显示 24 个飞书工具和授权范围选择。

已使用当前用户授权实测身份接口，身份匹配。后续用户已补齐搜索等权限，目前真实 token 含 8 项个人权限；此前搜索和列目录的缺权限记录已不代表当前状态，未读取真实文档正文，也未对用户真实飞书数据执行新增写入。代码能力不等于已授予权限；需要在飞书后台开通、发布后，在客户端按业务范围授权。

## 0.7.1 纠正与界面简化

移除飞书按业务域选择授权，改为服务器全量申请、自动选择和刷新已授予的 token。旧客户端传 group 参数也不会再缩小请求；旧凭证和已发起的授权任务兼容保留，不覆盖个人连接。

官方 attendance/v1/user_tasks/query 文档要求 tenant_access_token；该操作已明确标记应用身份，缺少公司级受控接入时不再提示员工反复补个人权限，也不回退到共享管理员 token。

同时移除有赞页面的店铺选择板块。服务器继续自动取得店铺列表并按店铺保存会话，工具的全部／指定店铺查询范围保持原有执行方式。

0.7.1 回归：后端 239 项、CLI 127 项和 55 个子测试通过；两个退役登录运行时测试仍不运行。线上使用现有个人授权实测基础搜索、新云空间搜索和根目录列表成功，身份匹配；没有执行真实业务写入或替员工批准新授权。
