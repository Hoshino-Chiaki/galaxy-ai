# 飞书考勤查询核验

当前权限规则已修正：查询他人使用 Galaxy 的 `feishu:attendance:company:read` 权限，默认给 Galaxy 管理员；不要求调用者是飞书企业超级管理员。平台角色仅作核验信息，平台应用授权范围仍生效。详见 [统一权限层与平台凭证](统一权限层与平台凭证.md)。下文“仅超级管理员可查他人”的规则为初版历史记录，已被此规则替代。

核验日期：2026-11-11。仅在服务器使用现有配置执行只读请求，没有更改代码、应用配置或业务数据；不保存凭证原值。

## 已确认的结果

- 现有企业应用成功取得应用身份凭证，返回有效期 7200 秒。运行时应采用接口实际返回的有效期。
- 凭证实际包含 `attendance:task:readonly`、`attendance:rule:readonly`，另有通讯录相关应用权限。
- 使用当前 Galaxy 管理员个人授权验证飞书身份，与已绑定的 open_id、tenant_key 一致；只采用该账号真实返回的 user_id，没有遍历其他员工。
- 使用应用身份调用 `POST /open-apis/attendance/v1/user_tasks/query`，`employee_type=employee_id`，查询该员工 20261111 当天：HTTP 200、业务 code=0、`user_task_results` 长度为 1。
- 这表示取得一条员工考勤结果，不等同于只有一次打卡，也不能据此判断全天已完成出勤或全公司数据均可访问。本次没有测试其他员工、整月统计、请假或加班明细。

## 原接入缺口

`backend/xingxu/feishu/service.py` 对应用身份操作直接返回 `feishu_application_identity_required`。`backend/feishu/cli/main.go` 的凭证提供者也只支持个人身份 UAT。因此，现有配置虽然已能通过官方接口查询考勤，AI 工具仍无法完成该调用。

目前飞书目录仅接入考勤 `user_tasks.query`。它的输入是员工 ID 列表、开始/结束工作日，可选忽略无权限员工、包含离职员工和加班结果。单次员工列表最多 50 人。上游目录将它标成 write，但它是只读查询；后续接入需要核对并修正本地权限分类，不能仅按 POST 推断业务写入。

## 接入方向

1. 在飞书模块增加应用身份凭证获取与按企业应用隔离的缓存；临近失效重新申请，不使用个人 refresh token。与员工 OAuth 凭证分别管理。
2. 仅为明确支持应用身份的工具选择该身份，不把应用 token 作为所有个人权限不足时的通用回退。当前模型只调用 galaxy_cli 的入口保持一致。
3. 公司授予应用的数据范围与 Galaxy 当前调用者的业务权限都要生效。员工默认只能查询与本人绑定的员工 ID；授权管理员才能查询获准的其他人员范围，不能只凭模型传入任意 user_ids 决定授权。
4. 先接通本人查询，再验证明确授权的员工范围；批量查询按接口上限拆分，保留无权限/无效员工列表。没有取得数据不能解释为无人打卡。
5. 打卡结果、原始打卡流水和统计报表分别核对接口与权限；机器人周报是展示入口，不能用收到消息来推断本应用的数据权限。

## 实现

授权完成后，服务器使用应用身份查询当前绑定 open_id 对应的通讯录资料，检查 `is_tenant_manager` 的实际布尔值。仅明确为 true 才认定企业超级管理员；false 记录为企业成员（非超级管理员），不能据此断定是否有其他管理角色。字段缺失、缺权限、网络异常保留未确认状态，不依据 Galaxy 管理员角色、应用开发者身份或某次查询成功推断管理员。

每次考勤调用重新核验当前个人身份和管理员标记。没有明确的超级管理员确认时，只允许该个人身份的员工 ID；调用参数省略 user_ids 时自动填入本人。应用 token 只允许在已明确登记的考勤操作中使用，不能回退给其他个人工具。token 在服务端按应用版本缓存，到期重新获取；权限补齐后遇到权限错误会重新申请一次凭证，无需等待旧凭证自然到期。

权限导入 JSON 包含原有个人权限及以下应用权限：

```json
{"scopes":{"tenant":["contact:contact.base:readonly","contact:user.employee:readonly","contact:user.employee_id:readonly","attendance:task:readonly"]}}
```

管理员识别接口首次实测返回 99991672，缺少 `contact:contact.base:readonly`。本人考勤不受管理员识别缺权限影响；查询其他员工必须等待官方接口实际确认。此实现没有把应用管理员等同于考勤管理员，也没有开放部门考勤管理员的管理范围；该范围需后续使用可核验的业务授权信息接入。

部署后已用 Galaxy CLI 应用身份实际查询当前绑定账号 20261111 本人考勤，返回一条员工考勤结果。通讯录校验也已成功，当前账号 `is_tenant_manager=false`；应用配置保持原样，个人连接仍有效。实际返回的完整业务数据没有写入核验文档。

最终飞书后端专项测试 29 项通过，CLI 回归 121 项及 45 个子测试通过，Go 隔离测试 3 项通过，669 个官方命令入口均可解析。扩大后端回归有 253 项通过，另一个目录数量断言仍按开发目录包含暂停的有赞商品搜索计数（37），生产目录为 36；CLI 同类 3 项目录断言不计入本次发布门槛。两个退役登录程序用例及两个未部署商品搜索用例未纳入有效回归，没有为了匹配这些断言部署有赞改动。

核验摘要（无凭证、无真实考勤明细）保存在 `artifacts/feishu-attendance-20261111.json`。
