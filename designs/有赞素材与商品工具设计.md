## 统一约定

- 工具全部归属 `youzan` 分类，每个工具独立一个 Python 文件。下面是计划文件，不在本次创建执行模块。
- AI 只使用 `galaxy_cli`，不获得 Shell、任意 HTTP 请求、任意目录读写或 SID/token 导出能力。
- 登录用户、工作区、当前店铺、SID、商家页面 CSRF、必要会话 Cookie 由服务端确定，通过已有私有分类上下文提供。参数不接受用户身份、店铺凭证、Cookie、供应商身份或上传凭证。
- 本次成功请求带有 SID、若干会话 Cookie 和 `csrf_token`。仅凭记录无法证明每个 Cookie 都必需，也不能保证当前 CRM 的 CSRF 可以原样用于所有商家接口。实现时应先用当前账号对素材分类、商品详情做只读验证，必要时从对应商家页面获取当前 CSRF。
- 不混淆三个概念：素材分类保存图片；商品分组用于店铺商品归类；商品类目是“母婴用品 > 童鞋… > 运动鞋”这样的行业类目。三套 ID 不能互用。
- ID 在模型输入中统一使用十进制字符串，不能用商品编码、条码、SKU 编码代替商品 ID 或 SKU ID。适配器按上游接口要求转换。
- 有赞业务响应原样返回完整 JSON，不追加无关包装、删减业务字段或截断结果；凭证明文不进入模型结果。不同接口字段可能采用 snake_case 或 camelCase，描述须说明各自解析路径。
- 上游 HTTP 200 不代表成功，必须检查业务 `code`；不能把上传失败、保存失败描述为成功。
- help 仍只返回 `tool/category/description`。描述用一段文字解释必填、可选字段、输入单位、输出及解析，不写抓包、研究文件或内部来源。

供模型使用的一段式 help 文案见同目录 `有赞工具help草案.json`；该文件仅是设计草案，不会被运行时自动加载。

## 六个工具的输入和输出

### 1. youzan.material-category

计划文件：`galaxy_cli/tools/youzan/material_category.py`。

命令：

```text
galaxy-cli youzan material-category list
galaxy-cli youzan material-category create --input '{"name":"TEST","parent_id":"上一步返回的父分类ID"}'
```

`list` 无必填参数，只查图片分类。输出为完整有赞响应：`data` 数组的 `categoryId/categoryName/parentCategoryId/categoryType/count/subCategoryCount` 用于识别分类和层级。不要假设数组第一项就是用户要上传的分组。

`create` 必填 `name`，可选 `parent_id`。省略父分类时从当前店铺分类列表识别 `categoryType=5` 的“自定义分组”根目录，不能写死示例中的 ID。显式父分类须属于当前店铺且允许创建子分类；“未分组”等系统分类不能当普通父分类。成功响应 `data` 是新分类 ID，创建后重新查询分类列表确认。

接口映射：

- `GET /v4/materials/attachment/multi-category/tile-query.json?mediaType=1`
- `POST /v4/materials/attachment/multi-category/create.json`，JSON：`categoryName,parentCategoryId,mediaType=1,csrf_token`。

分类工具进一步纳入以下结构可推导的动作，不另拆新工具：

- `rename --input {category_id,name}`：先读当前父分类，使用 `PUT /v4/materials/attachment/multi-category/update.json`，字段为 `categoryId,categoryName,parentCategoryId,mediaType`。前端脚本有明确调用，当前没有实际改名请求样本。
- `move --input {category_ids,parent_id}`：读取原父分类，使用 `PUT /v4/materials/attachment/multi-category/move.json`，字段为 `categoryIds,mediaType,oldParentCategoryId,targetCategoryId`。不同原父分类分组处理，禁止移到自身或后代。前端显示含子分类的分组可能移动失败；上游 data 中的失败分类列表必须解析，不能仅凭 code=0 就宣称全部移动成功。
- 删除也可以保留设计，但脚本显示存在 deleteType，可能影响分类内素材；其选项语义尚未核实，本次不猜测“删除分类是否删除图片”，不将其加入可直接提交的参数。

改名/移动使用独立的 `youzan:material:category:update` 权限，不由分类查询权限推导出写权限。

### 2. youzan.material-list

计划文件：`galaxy_cli/tools/youzan/material_list.py`。

```text
galaxy-cli youzan material-list --input '{"category_id":"分类ID","page":1,"page_size":15}'
```

必填 `category_id`；可选 `page`（默认 1）、`page_size`（默认取已确认的页面值 15）。只列图片；另纳入可选 `keyword` 设计，前端脚本明确将其传给素材列表接口，并要求搜索词至少 3 个字符。实现时先读取平台的搜索支持状态，不支持则明确返回 unsupported_search，不能忽略关键词后返回不相关列表；此能力属于脚本可推导、尚未实际查询验证。

使用商品选图器的完整响应结构，`data.items` 为图片数组，`data.paginator` 为分页信息。单张图片读取 `attachmentId,attachmentTitle,attachmentFullUrl,attachmentUrl,attachmentSize,width,height,fileExt` 等；所有原始字段保留。`attachmentId` 才是供商品主图使用的素材 ID，不使用文件名推测 ID。`meta` 有时是 JSON 字符串，需解码才能读取其中附加信息。

接口：`GET https://materials.youzan.com/v4/materials/api/upload/materials/list`，参数 `categoryId,pageNum,pageSize,mediaType=image,p`；`p` 与 `pageNum` 同步；存在关键词时额外传 keyword。素材中心另有 `/v4/materials/attachment/image/query.json`，同样返回 `items/paginator`，不将两套响应字段盲目拼接。

### 3. youzan.material-upload

计划文件：`galaxy_cli/tools/youzan/material_upload.py`。

```text
galaxy-cli youzan material-upload --input '{"category_id":"分类ID","url":"https://example.com/image.jpg"}'
galaxy-cli youzan material-upload --input '{"category_id":"分类ID","path":"input/test-image.jpg"}'
```

必填 `category_id`；`url` 和 `path` 必须二选一。不接收输出目录、任意目标接口、upload token、Cookie 或供应商 ID。用户尚未说明分类时，按全局提示词询问放在哪个分组，或者是否选择“未分组”；不可自行替用户选分组。“未分组”也要从当前店铺分类列表获得真实 ID，不用 0 或历史 ID 代替。

网络方式已确认：`POST /v4/materials/api/shop/fetchPubImg.json`，表单 `attachment_url,categoryId,channel=wsc_web,csrf_token`。成功返回完整响应；`data.attachment_id` 是素材 ID，`attachment_full_url/attachment_url` 是有赞原图地址，`attachment_size/width/height` 为文件信息。返回地址可能改写扩展名，不能仅凭 URL 后缀判断真实图片格式。本次记录中曾出现 `file_ext/meta.format` 与最终地址后缀不同。

本地方式的 path 参数已纳入工具设计；实际启用前完成上传链路联调，不需要等所有商品字段都有独立样本后才实现。已从前端脚本定位到以下流程，但待成功样本确认响应结构和当前策略：

1. `GET /v4/materials/api/image/policy.json` 获取当前图片策略。
2. `POST /v4/materials/api/shop/pubImgUploadToken.json`，传 `channel`，使用当前商家会话和 CSRF；读取 `uptoken`。
3. `POST https://upload.qiniup.com`，multipart 表单字段是 `token,file,x:categoryId`。
4. 解析上传返回值，并重新查询目标分类确认入库，返回完整实际业务结果。不能仅拿到 token 就声称上传成功；未捕获的回调或补充参数需按成功样本核实。

本地路径权限沿用文件工具已建立的账号工作目录：只接受其内部相对路径，逐层用目录句柄打开，拒绝绝对路径、目录跳转、隐藏路径、编码路径、符号链接、硬链接和特殊文件。不会给 AI 读取整个 `~/Pictures` 或服务器其他目录的权限。

网络地址仅允许合法公网 HTTP/HTTPS 图片地址，拒绝带账号密码的 URL、回环及私有网络目标。图片内容需要真实可解码，不能把 HTML 当图片。直接交给有赞抓取时，上游的重定向和 DNS 行为不由本工具控制；若部署要求严格限制抓取目标，应改为服务端受控下载、验证后走本地上传，完成后仍保留同一工具输入。

测试素材已定位为 `~/Pictures/wp16114694-shiina-hiyori-wallpapers.jpg`，约 292 KB；这是 Pictures 顶层的唯一图片，不包含子目录里的壁纸。真正测试时，由开发人员把这一个指定文件放入测试账号工作目录的 `input/test-image.jpg`，工具只读该相对路径。本次仅设计，不复制、不上传。

### 4. youzan.product-get

计划文件：`galaxy_cli/tools/youzan/product_get.py`。

```text
galaxy-cli youzan product-get --input '{"product_id":"4903044508"}'
```

必填 `product_id`，返回完整有赞响应 `code/msg/data`，不裁剪详情、SKU 或任何其他业务数据。

主要解析：

- 基本信息：`data.id,title,goodsNo,barcode,alias,updateTime`。
- 主图和详情：`picture` 为有序数组；`content` 是详情 HTML；还可能有模板/组件信息。
- 商品分组：`tag/actualTag` 及 `itemAssistDetail.groups`。
- 价格：`itemPriceParam`；SKU 价格在 `itemStockParam.stock[].price`，金额单位为元。以十进制解析，保留原始字符串精度。
- 库存：`itemStockParam.totalStock/spotStockNum/stock`，结合具体 SKU、是否销售和锁定量解释，不能拿顶层 `num=0` 当成所有 SKU 售罄。
- 分销约束：`extraParam.fenXiaoParam`，包含供应商、供货价和各 SKU 建议零售价区间；这些是当前商品的数据，不是所有商品通用的规则。
- 编辑与上下架：`isDisplay,itemAssistDetail.isEditLock/isLock/pageLockList` 等作为上游状态信息，最终以接口校验为准。

接口：`GET /v4/goods/publish/api/item/get?id=商品ID&withoutSubItemDisplay=true`。

### 5. youzan.product-options

计划文件：`galaxy_cli/tools/youzan/product_options.py`。

```text
galaxy-cli youzan product-options groups --input '{"product_id":"4903044508","page":1}'
galaxy-cli youzan product-options sku-values --input '{"product_id":"4903044508","spec_id":"12"}'
galaxy-cli youzan product-options detail-templates --input '{"product_id":"4903044508","page":1}'
galaxy-cli youzan product-options delivery --input '{"product_id":"4903044508"}'
galaxy-cli youzan product-options shops --input '{"product_id":"4903044508"}'
```

`product_id` 必填，使查询明确关联当前店铺的商品；`sku-values` 额外必填 `spec_id`。其他可选输入只对相应子命令有效，例如商品分组的 `page/parent_id/keyword`，模板的 `page/page_size`。无关字段必须报错，不能混入上游请求。

- 商品分组：`/v4/goods/tag/listMultiLevelGroupPage.json`、`querySubGroupList.json`、`queryGroupListJSON.json`，用于查询目录和已选组。关键词搜索已在商品分组请求中出现，不能据此宣称“商品搜索”或“素材搜索”已支持。
- 规格候选：`/v4/goods/publish/api/sku-tree`、`/shop/v2/showcase/skuProperty/skuValue.json`。能读取候选值，不代表允许修改该分销商品的规格。
- 详情模板：`/v4/goods/publish/api/pageQueryDetailTemplate`，完整响应的 `data.items` 为模板、`data.paginator` 为分页。只确认列表读取，模板应用/编辑序列化还需样本。
- 配送：`/v4/goods/publish/api/delivery-setting`，读当前店铺配置；它不是分销商品可改物流的证明。
- 分店：`/v4/goods/publish/api/sub-shop-list` 及商品关联分店列表，供后续需要修改销售终端范围时查询。

每个子命令返回所调用接口的完整实际响应，不聚合大量无关选项。店铺 ID 从当前登录上下文取得，不能由 AI 指定其他店铺。

### 6. youzan.product-update

计划文件：`galaxy_cli/tools/youzan/product_update.py`。

```text
galaxy-cli youzan product-update preview --input '{"product_id":"4903044508","changes":{"goods_no":"45510","barcode":"45510","title":"新的名称","append_image_ids":["已查询或上传成功的图片ID"]}}'
galaxy-cli youzan product-update apply --input '{"product_id":"4903044508","base_update_time":1794176625000,"changes":{"title":"新的名称"}}'
```

以上仅为输入示例，不应原样执行到示例商品。以下参数属于设计接口，未注册为可执行工具。

必填 `product_id,changes`；`apply` 还要提供最近读取/预览得到的 `base_update_time`。changes 是明确命名的差异对象，至少包含一项实际变更。字段省略表示不修改，不能把缺省值批量写回。允许设计尚未单独操作但已有明确保存字段的能力；服务端检查当前商品类型、字段约束和权限，不能将预览通过当作上游保存成功。

设计中的 changes：

| 参数 | 输入与语义 | 对应上游字段 | 证据状态 |
|---|---|---|---|
| `goods_no` | 字符串，空字符串清空商品编码 | `goodsNo` | 已确认修改 |
| `barcode` | 字符串，保留前导零，空字符串清空 | `barcode` | 已确认修改 |
| `title` | 非空字符串，使用当前商品名称校验规则 | `title`，保存前调用名称校验接口 | 已确认修改 |
| `append_image_ids` | 素材 ID 字符串数组，保留原图并按顺序追加、去重 | 合并后的 `picture` 数组 | 已确认追加 |
| `image_ids` | 完整目标主图 ID 数组，按此顺序保存；可实现替换、移除和重排；与 append_image_ids 互斥 | `picture` | 同字段结构推导 |
| `group_ids` | 商品分组 ID 数组，表示完整目标集合；空数组表示移除可取消的商品分组 | `tag` | 已存在数组映射，写入待联调 |
| `price` | 单规格商品零售价，十进制字符串，单位元 | `itemPriceParam.price` | 已存在金额字段，写入待联调 |
| `origin_price` | 划线价，十进制字符串，单位元；null 表示清空 | `itemPriceParam.origin` | 已存在金额字段，写入待联调 |
| `sku_updates` | 按 SKU ID 修改的数组，单项结构见下文 | `itemStockParam.stock` | 已存在明细结构，写入待联调 |
| `hide_stock` | 布尔值，是否在商品详情和购物车隐藏剩余件数 | `itemStockParam.hideStock`，适配为 0/1 | 已存在布尔/数字映射，写入待联调 |
| `detail_html` | 商品富文本详情 HTML；只有当前商品详情模式支持时接受，不随意覆盖组件式详情 | `detailEdit/content/components` 的配套序列化 | 字段已定位，序列化需联调 |
| `is_display` | 布尔值，商品立即上架/下架；不包含删除商品 | `isDisplay`，适配为 0/1 | 已存在状态字段，写入待联调 |
| `sale_scope` | `{on_shop_ids:[...],off_shop_ids:[...]}`，显式更改指定销售终端；两集合必须互斥 | `displayOnKdtIds/displayOffKdtIds` | 已存在列表映射，影响范围需联调 |

多规格商品不能只传顶层 price 后就假定全部 SKU 都改价；使用 sku_updates 明确要改哪些 SKU，适配器按前端计算规则维护商品汇总价。金额使用 Decimal 处理，不能把“元”当“分”，也不能用二进制浮点运算产生尾差。

`sku_updates` 单项必填 `sku_id`，以下字段均可选，但至少传一项：

| 参数 | 类型与语义 | 映射/限制 |
|---|---|---|
| `price` | 十进制字符串，元 | 当前 SKU 的 price；分销 SKU 需遵守实时 min/max 零售价限制 |
| `is_sell` | 布尔值 | isSell 的 0/1；不通过修改 disableStatus 绕过供应商禁用 |
| `stock_num` | 非负整数，表示目标库存数量，不是增减量 | stockNum 及相应的编辑标志/汇总；仅适用于允许本店维护库存的商品 |
| `code` | 字符串，SKU 编码，保留前导零 | code；当前商品不允许维护时拒绝 |
| `barcode` | 字符串，SKU 条码，保留前导零 | barcode；当前商品不允许维护时拒绝 |

同一 SKU ID 不允许重复；必须属于当前商品和店铺，不能仅凭颜色/尺码文字猜 ID。未指定的 SKU 原样保留。分销商品的供应商库存、供货价、规格和禁用状态不因为存在类似字段就成为本店可写数据；商品类型不支持时返回明确的 unsupported_field 或 upstream_rejected。

图片参数从当前店铺图片列表或上传结果取得素材 ID；服务端从自己的查询/上传记录解析 URL、宽高，不让模型随便拼接 CDN 地址或提交任意图片对象。image_ids 是完整目标列表，不能为空；移除图片只是解除商品关联，不顺带删除素材库文件。采用当前商品的图片数量限制，当前页面提示最多 15 张，不将其当作所有商品固定上限。

例如，以下是可以进入实现联调的差异设计，不表示这些修改已经在示例商品执行过：

```json
{
  "product_id": "测试商品ID",
  "changes": {
    "group_ids": ["当前店铺商品分组ID"],
    "origin_price": "199.00",
    "hide_stock": true,
    "sku_updates": [
      {"sku_id": "当前商品SKU_ID", "price": "139.00", "is_sell": true}
    ]
  }
}
```

另有一些页面项目虽可设计语义，但当前缺少确定的枚举、ID 分配或保存映射，先保留设计位而不宣称已能直接提交：

- 定时开售：语义为 `sale_schedule`，需要明确启用/取消、时间及当前店铺时区；不能仅凭 startSoldTime 字段就猜 soldTime 枚举或时间单位。
- 预售与备货：语义为 `presale/prepare_time`，需要核对不同预售类型及时间规则；不能把默认值 -1/0 当成所有模式通用值。
- 规格重建：语义为 `specification_changes`，包括更名、增加/删除值、新建 SKU；必须补齐规格/SKU ID 的申请和关联逻辑，不生成不存在的 ID。修改已有 SKU 的价格或销售状态不依赖开放规格重建。
- SKU 规格图、重量：候选映射为 skuName1Value 的 imgUrl、skuWeight；重量具体数值键和规格图显示开关仍需定位，再固定输入类型与单位。
- 行业类目、商品参数、资质：可预留 `category_properties` 设计，但当前保存例子不足以闭合参数与资质接口，不能把商品分组 ID 直接填入。
- 普通自营商品配送：可预留 `delivery` 的运费模板/时效模板参数；只对上游允许维护的商品开放。本次分销商品页面明确不支持，不设计绕过路径。

`preview` 不发保存请求，只取得当前商品、做校验并返回最小结果：`product_id,base_update_time,changes`，其中 changes 为字段级 `field/before/after` 数组；有实际限制才返回 `warnings`。

`apply` 对接 `POST /v4/goods/publish/api/item/update/_textarea_`，本次记录的 Content-Type 为 `application/json`。AI 传少量差异，适配器负责读取最新商品、构造有赞需要的完整保存体、合并允许变更；不能把原始 GET 响应直接当 POST 请求体。记录中 GET、POST 的字段和类型并不完全相同，例如 `itemSellParam`、配送配置、SKU 编辑标志、详情内容与组件。

保存体包括现有的 `id,alias,picture,tag,itemPriceParam,itemStockParam,itemSellParam,itemDeliveryParam,extraParam,...`，这些是适配器维护原状态需要的字段，不是全部开放给模型修改的参数。特别是：

- 不修改库存时，应遵循当前前端的 `isStockNumEdited/isSkuStockNumEdited` 序列化逻辑，不能因为复用了 GET 中的 true 值就触发库存覆盖。
- 不修改详情时保留现有详情，正确处理 `detailEdit/content/components`，不把空模板或错误编码写回。
- `displayOnKdtIds` 等销售终端范围不能用固定样本回填；读取当前配置并保留原状态。
- 供应商 ID、供货价、供应商库存不开放为 changes；本店允许修改的分销零售价仍需遵守上游实时限制。自营库存修改与供应商库存覆盖是两种不同能力。

并发：按“工作区 + 当前有赞连接 + 店铺 + 商品”加写锁，保存前重新读取并对比 `updateTime`；过期版本返回冲突，不覆盖。上游记录未证明有原子条件更新接口，因此不能承诺阻止有赞网页或其他外部系统恰好同时写入的全部竞态；适配器保存后必须回读核对。

成功 apply 返回完整上游保存响应；工具只在回读确认本次变更生效后将调用标为成功。保存请求断网后不得盲目重试：先回读，能确认已生效则返回实际状态，不能确认则明确返回“状态待核实”。如果保存返回成功但回读失败，错误要明确 `save_may_have_succeeded`，避免 AI 重复追加或反复修改。

## 能改到什么程度

“纳入设计”表示已经定义业务输入、字段映射与校验方式，不表示已经实测成功或已经上线。

| 内容 | 当前设计范围 | 证据和边界 |
|---|---|---|
| 商品名称、商品编码、商品条码 | 预览与修改 | 已有保存及回读证据 |
| 主图追加 | 追加素材图片 | 已有保存及回读证据 |
| 主图替换/删除/重排 | 用 image_ids 提交完整目标列表 | 与 picture 同一字段结构推导，后续验证顺序和限制 |
| 商品分组 | group_ids 完整目标集合 | 已有查询和 tag 保存结构，写入待验证 |
| 零售价、划线价、SKU 价格 | price/origin_price/sku_updates.price | Decimal 元单位；区分多规格，遵守当前分销 SKU 的价格区间 |
| SKU 销售状态 | sku_updates.is_sell | 已有 isSell 映射，不修改供应商禁用状态 |
| SKU 编码/条码 | sku_updates.code/barcode | 当前商品允许时维护，保留前导零 |
| 隐藏库存 | hide_stock | hideStock 的布尔映射，写入待验证 |
| 自营库存 | sku_updates.stock_num | 非负目标值，正确标记库存编辑；供应商库存不开放覆盖 |
| 富文本详情 | detail_html | 只对支持的详情模式开放，需核对组件序列化；不默认清空组件 |
| 立即上下架、分店销售范围 | is_display/sale_scope | 读当前范围，校验总部/分店权限及影响范围 |
| 定时开售、预售、备货时间 | 已设计语义，保留参数位 | 时间、枚举和配套字段尚未核实，不能宣称可直接提交 |
| 规格重建、SKU 新增/删除 | 已设计语义，保留参数位 | 缺 ID 分配及关联链路；不阻塞已有 SKU 价格/状态设计 |
| 规格图、重量、行业类目、属性和资质 | 保留设计位 | 尚缺完整字段/接口映射，需要进一步定位 |
| 供货价、供应商库存、供应商身份 | 不提供修改参数 | 不属于当前分销商可维护能力 |
| 此分销商品的运费/配送 | 不提供修改参数 | 页面明确不支持，不用接口尝试规避 |

## 服务端权限和隔离

建议最小授权：

| 工具/动作 | 权限 |
|---|---|
| material-category list、material-list | `youzan:material:read` |
| material-category create | `youzan:material:category:create` |
| material-category rename/move | `youzan:material:category:update` |
| material-upload | `youzan:material:upload`，并要求能读取当前分类 |
| product-get、product-options、product-update preview | `youzan:product:read`；preview 不因此获得写权限 |
| product-update apply | `youzan:product:read` + `youzan:product:update`；图片变更还需素材读取权限 |
| 商品价格变更 | 基础修改权限 + `youzan:product:price:update` |
| 本店库存数量变更 | 基础修改权限 + `youzan:product:stock:update` |
| 上下架/销售终端变更 | 基础修改权限 + `youzan:product:display:update` |

新写权限不自动给所有员工。后台角色/授权策略决定谁有权限，AI 提示词不能授予权限。用户在聊天中决定业务操作，不增加无关的确认流程；权限检查、文件目录边界和上游字段校验必须落在服务端。

现有 `YouzanService.tool_credentials` 目前把取分类凭证硬绑定为 `youzan:customer:read`，扩展这些工具时应改为按实际命令所需权限授权，不应为了上传图片而强迫授予客户数据读取权限。

执行前、排队后、调用完成后复核登录、权限和当前连接。凭证仍按当前登录用户与工作区隔离；店铺、SID/CSRF 或连接版本发生变化时拒绝继续写入。类别 ID、商品 ID、SKU ID、素材 ID 都必须验证属于当前店铺，不能仅凭 ID 格式正确就发起操作。

本地图片不能通过 URL 模式的 `file://`、路径编码、系统目录链接等绕过相对路径限制。上传凭证只在内存中用于指定上传服务，不进入业务结果、help、审计日志或模型上下文。上传 HTTP 客户端与有赞会话客户端分开，不把 SID、Cookie 或商家请求头发送到第三方上传域名。

审计保存调用者、工具、当前店铺、目标商品/分类/素材、变更字段名、执行结果，不记录 Cookie/token、图片二进制、完整商品详情或所有请求原文。

预览是否必要、用户未指定分组时如何询问、批量操作策略写入可编辑的全局提示词；权限、所有权、数据类型、明确字段映射及商品类型限制、目录边界由代码执行。尚未单独操作但可推导的字段可纳入实现联调；不提供任意 JSON 路径透传来绕过约束。不得增加一轮对话只能调用几次工具之类的业务配额。

## 还需要补充什么

当前材料已经足够完成基础工具设计，不需要另给账号密码或手填 SID/token。要实施并验证更完整能力，按优先级补：

1. **一次本地图片上传成功的完整记录**：从打开上传面板前开始，到选文件、明确分类、上传完成、列表看到图片结束。重点是图片策略、申请 uptoken、`upload.qiniup.com` 上传及可能的回调。当前只有脚本流程，没有实际完整上传请求。保留响应正文，避免只记录选文件后的静态页面。
2. **商品列表按名称/编码搜索的一次记录**：如果希望用户只说“修改 45510 这个商品”而不提供商品链接/ID，需要商品搜索工具。当前记录中的“商品分组搜索”不能替代商品搜索。
3. **可推导字段不必逐项先补样本才设计**：价格、商品分组、SKU 销售状态、隐藏库存等已按现有结构设计。后续可以直接在测试商品上完成实现与回读验证；用户补录相应成功操作有助于更快确定细节，但不是设计的前置条件。
4. **真正缺链路的部分**：规格/SKU 新增删除、复杂组件详情、定时开售/预售枚举、行业类目与资质仍需进一步定位；可补相关成功操作记录。自营库存用自营测试商品，不用分销商品推导供应商库存可写能力。

不要求继续开发聊天图片上传，也不要求把用户 Pictures 目录开放给 AI。
