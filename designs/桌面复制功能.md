# 桌面复制功能（0.7.2）

问题：回复和飞书权限 JSON 原先调用 navigator.clipboard.writeText。Electron 主进程统一拒绝浏览器权限请求，桌面环境中的复制因此失败；回复组件原先还会吞掉失败信息。

通过 preload 暴露 clipboard.writeText，主进程使用 Electron 原生 clipboard.writeText 写入系统剪贴板。IPC 沿用 trusted(event) 校验，仅接受当前主窗口的可信页面和字符串参数。没有新增剪贴板读取通道。

src/clipboard.ts 统一两处复制入口；回复复制完整原始 Markdown 文本，保留表格、中文和换行。复制成功显示“已复制”，失败显示“复制失败，点击重试”。飞书权限 JSON 同样使用该通道。

Windows 验证使用 scripts/verify-copy-windows.cjs：操作实际应用按钮，从现有对话读取预期内容，在 Windows 内存中比对系统剪贴板；同样核对权限 JSON，并检查非字符串输入被拒绝。测试脚本不发送 AI 消息或修改服务器配置。STA PowerShell 包装脚本在 finally 中恢复测试前的系统剪贴板，不打印或保存原有剪贴板内容。

验证结果：前端构建和 Electron 主进程语法检查通过。Windows 10 上覆盖安装 0.7.2 后，实际点击回复及权限 JSON 的复制按钮，系统剪贴板与源文本逐字一致；非字符串输入被拒绝，剪贴板读取未暴露。测试没有发送 AI 消息或修改服务器配置，原剪贴板已恢复。
