## 存储归属

MySQL 继续作为账号、登录会话、权限、人员组织、AI 配置、企业飞书应用和公共工具配置的权威数据源。个人聊天、渠道连接、文件索引、上传记录和工具审计改用账号文件。文件模式不向这些个人数据的旧 MySQL 表写入，也不会在文件读取异常时偷偷回退到旧表。

```text
/opt/galaxy-ai/backend/private/
├── ai-secret.key                      # 现有全局加密密钥，保留原文件
└── accounts/
    ├── .owners.json                    # 不可变身份到账号目录的映射
    ├── .ready.json                     # 完成迁移和逐项校验后才生成
    ├── .system-audit.json              # 匿名调用、已删除用户的历史审计
    ├── .*.lock                         # 仓库进程间锁
    ├── chiaki/
    │   ├── account.json
    │   ├── browser/                    # 此人的所有渠道共用一个持久浏览器配置
    │   │   ├── .channel-bindings.json
    │   │   └── .galaxy-profile.lock
    │   ├── channels/
    │   │   ├── youzan/connection.json
    │   │   ├── feishu/connection.json
    │   │   └── guanjia/connection.json
    │   ├── chats/<对话ID>.jsonl
    │   ├── workspace/                  # 文件工具、上传与工作资料
    │   ├── files/
    │   │   ├── metadata.json
    │   │   └── published/              # 发布后的下载副本
    │   ├── uploads/requests.json
    │   ├── tasks/dsh/<对话ID>/           # 沙盒文件、检查点、续接状态
    │   ├── runtime/cli/                # CLI 用户环境，不包含浏览器程序
    │   └── logs/tool-audit.json
    ├── yuzhuo/
    └── TEST/
```

账号目录按用户名命名；特殊字符编码，危险或过长名称使用安全替代名。目录归属绑定 `workspace_id + user_id`，不能由模型、客户端参数或渠道账号决定。修改用户名保留原目录映射，防止错误创建第二份数据。目录权限 `0700`，文件 `0600`，由 `galaxy-ai` 用户持有。读取拒绝符号链接、硬链接及特殊文件。

公共浏览器程序、Playwright 和 CLI 程序仍共用现有安装，未为每个账号重新安装浏览器。每位用户只有自己的 `browser/`，它保存 Cookie、LocalStorage、缓存等个人状态；不同用户不会共用该配置目录。同一用户的不同渠道使用该目录并通过文件锁排队启动，防止 Chromium 同时打开同一配置。

当前有赞接入已经使用该目录。飞书 OAuth、管家等已有接口继续使用各自加密连接文件；以后增加浏览器渠道登录时必须复用账号的 `browser/` 和同一把配置锁。

## 聊天与文件行为

每个对话一个 JSONL 文件：首次写入 `snapshot`，后续追加 `update` 事件，正常续聊只追加新增消息及变化字段。每次提交落盘并 `fsync`，读改写使用进程间锁。进程中断留下的末尾不完整行不视为已提交，下次写入前截除；完整但损坏的内容明确报错。

模型内部上下文、工具结果、思考字段和 DSH 检查点仍保留原有含义。对外返回继续隐藏内部上下文。新对话、续聊、列举、删除全部走账号文件；删除对话同时清理其附件、上传和 DSH 状态。

下载仍使用 `/files/<文件名>` 或 `/api/v1/files/<ID>`，继续检查登录身份、工作区、对话和成功发布记录。个人发布文件实际位于该账号的 `files/published/`。原来由管理员手工放在 `hosted-files` 的公共共享文件保留原有语义。共享业务操作锁和临时代理套接字仍放在公共运行目录，不包含跨账号共享的浏览器登录状态。

## 运维、备份与回退

日常使用现有 `galaxy-ai-db-backup.timer`，每日备份脚本已扩展为 SQL + `ai-secret.key` + `accounts/`。备份期间持有仓库和浏览器的共享锁，保留现有备份保留数量配置。完整备份仍应额外包含手工共享文件和部署配置。

在其他环境重新实施时，先完整备份并停后端和 DSH，再执行；不要在运行中导入：

```bash
cd /opt/galaxy-ai/backend
export GALAXY_DATABASE_CONFIG=/etc/galaxy-ai/database.json
.venv/bin/python -m xingxu.migrate_accounts                  # 只读预检查
systemctl stop galaxy-ai
systemctl stop galaxy-dsh
.venv/bin/python -m xingxu.migrate_accounts --apply
chown -R galaxy-ai:galaxy-ai private/accounts
# 确认校验完成后，再安装 deploy/account-storage/ 两个模板至上述 drop-in 位置
systemctl daemon-reload
systemctl start galaxy-dsh
systemctl start galaxy-ai
```

已完成迁移时再次 `--apply` 会拒绝覆盖；当前生产服务器不需要再执行一次。

若切换后已有新聊天或文件，不能直接关闭开关并恢复旧 SQL。先停止两个 Galaxy 服务，使用当前版本导出新增数据回旧存储：

```bash
cd /opt/galaxy-ai/backend
systemctl stop galaxy-ai
systemctl stop galaxy-dsh
export GALAXY_DATABASE_CONFIG=/etc/galaxy-ai/database.json
.venv/bin/python -m xingxu.migrate_accounts --rollback-to-mysql --apply \
  --rollback-backup /var/backups/galaxy-ai/account-storage-rollback-<时间>
```

导出会回写个人仓库到 MySQL，并将当前工作区、CLI 环境、浏览器和任务数据复制回原路径；被替换的旧目录先移入指定备份目录。逐项核对导出结果后，恢复切换前源码和服务配置、移除两个 `account-storage.conf`，再 reload/start。账号文件保留作回溯；以后重新启用必须重新核对数据权威源，不能直接复用旧 `.ready.json`。

不得删除或重新生成 `ai-secret.key`，否则已有渠道密码、SID 和模型密钥会失去解密能力。
