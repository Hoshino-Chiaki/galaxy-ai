# 有赞成本价接口核验与月度同步需求

核验日期：2026-11-16。仅查询公开官方文档，没有调用商品写接口、执行成本同步或建立定时任务。

## 本轮需求和状态

- 来源为管家婆，目标为聚水潭、有赞，每月更新一次；具体日期、时区和失败补跑方式尚未约定。
- 管家婆有较多零成本商品。老板仍在确认需求，不能自行决定将目标平台现有成本清零，也不能把零成本永久当成跳过规则。
- 待确认来源字段究竟是库存成本、参考成本，还是原打通系统读取的价格项；有限样本的零成本不代表全部商品成本为零。后续调查方法与边界见《20261116开发更新》，真实业务核验报告留在本地。
- 用户选择 DSH 作为编程执行能力。它可通过 shell 使用 galaxy-cli，但接入必须保留 Galaxy 服务端的当前账号、会话、门店权限检查。
- DSH/Python 执行能力在同日后续工作中已部署，见《DSH运行时接入》。DSH 工作目录本身不构成账号隔离；整个执行环境只能看到本账号被选中的文件，不能获得宿主机其他账号目录、管理员凭据或运行平台控制接口。

## 已确认的官方写入口

优先候选是 `youzan.item.incremental.update`，版本 `1.0.1`：

`POST https://open.youzanyun.com/api/youzan.item.incremental.update/1.0.1`

| 对象 | 参数路径 | 金额单位 |
| --- | --- | --- |
| 商品主信息成本 | `param.item_price_param.cost_price` | 分，整数 |
| 已有规格的成本 | `param.sku_list[].cost_price` | 分，整数 |
| 渠道商品成本 | `param.item_channel_params.item_price_param.cost_price` | 分，整数 |

商品以 `param.item_id` 定位；多规格需要准确匹配已有 SKU。11 元在上述以分计的字段中表示为 1100。金额转换应使用十进制定点运算。

注意：渠道规格的 `channel_sku_list[].cost_price` 文档写成元，而类型仍为 Long，和相邻字段单位不同。未经验证不能复用“乘 100”转换，也不能猜测文档错误。

官方权限表包括用户已列出的“商品更新”和“商品同步-零售”。这证明能力包层面存在对应接口，尚不证明现有 access_token 的实际授权、店铺版本、商品范围均适用。

文档列出的店铺范围包括零售连锁总部及高级版总部，但说明正文强调零售高级版总部，并要求新版类目。需要结合实际店铺、商品类型和主档/渠道关系验证，不可承诺所有门店均可直接更新。

这是成本更新的官方候选，无需预先认定必须重放 HAR 中包含几十项字段的后台提交。单个商品的最小可用请求、遗漏字段的实际效果、SKU 集合是否需传全、渠道是否同步，仍需测试商品验证。

## 回读与其他接口

`youzan.item.detail.get/1.0.0` 的官方响应定义含主商品、SKU、渠道的成本字段，可作为回读候选。定义有字段不保证实际店铺一定有值，必须用同一店铺和正确商品层级验证。此前 HAR 中读不到 costPrice，只能说明该后台请求样本没有返回，不能推导所有开放接口均读不到成本。

- [查询商品详情](https://doc.youzanyun.com/detail/API/0/2783)
- [有赞官方支持关于商品库与门店商品区别的答复](https://bbs.youzan.com/forum.php?mod=viewthread&page=1&tid=695963)

`youzan.item.price.update/1.0.0` 的旧结构化文档出现 `operate_type=1` 成本操作，但当前新版公开 Markdown 没列出这个参数。暂不将它作为已确认的成本专用接口：传错或遗漏操作类型可能落到零售价。

- [编辑商品价格当前文档](https://doc.youzanyun.com/v2/doc/cloud/token/HWZTwdVNJiEvWGkgfyNcNNYAnIh)

旧 `youzan.retail.open.sku.update.price/3.0.0` 公开说明是零售价/标准价更新，不能仅根据接口名称将其用于成本。

## 确认后再验证的内容

1. 明确管家婆成本字段、零值/空值规则、成本归属单位和总部/门店范围。
2. 用条码或稳定编码建立 SKU 对照；保留前导零，冲突和无法匹配项进入异常清单。
3. 先生成差异清单，再用指定测试商品验证最小成本更新、金额单位及正确层级回读，同时核对售价、库存、规格和上下架状态。
4. 确认读写闭环后再创建月度任务，保存旧值、执行结果、失败项和回读结果；幂等重试不得扩大原任务范围。

以上是后续实施条件，不代表用户需要重复批准已经明确授权的常规操作。本轮遵从“后续再等”的要求，不启用业务写入或月度调度。
