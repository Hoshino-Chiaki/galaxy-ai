# MCP 用户凭证隔离设计

状态：接入设计，尚未实现 MCP 调用和凭证存储。本次已实现两个独立用户、服务器鉴权与角色权限；此文档规定后续连接工具时的隔离方式。

用户已确定后续命令入口为 `galaxy-cli`：登录后从后端取得权限令牌并交给 CLI 存储，后面的工具调用自动携带该令牌，工具服务在执行时验证权限并拒绝未授权访问。权限令牌为用户调用工具的授权；下文中的第三方账号凭证为工具连接外部服务的凭证，两层分别管理。当前先完成 `help` 和自动注册，令牌能力留待后续实现，见 [CLI 说明](../galaxy-cli/README.md)。

当前聊天已接入受控的 `galaxy_cli` 调度，使用产品登录会话校验身份和命令权限，只授权 `help`。模型不能指定进程路径、环境、工作目录或用户身份；工具注册后还需单独授权执行。CLI 权限令牌下发、业务工具和 MCP 协议仍按后续计划实施，见 [工具执行权限](Galaxy工具执行权限.md)。

## 身份与归属

MCP 工具定义可在公司范围内共用。员工在第三方服务中的登录凭证属于具体用户的具体连接，用 `workspace_id + user_id + tool_id + connection_id` 标识。使用服务器签发的稳定用户 ID，账号改名后归属不变。

| 项目 | 共享或隔离方式 |
| --- | --- |
| 工具名称、参数结构、接口定义 | 管理员维护，可共用 |
| 第三方 access_token、refresh_token、Cookie | 每个用户及连接单独保存 |
| 浏览器上下文、持久浏览器目录 | 每个用户及连接独立 |
| MCP HTTP 会话和连接池 | 按认证身份和连接分开 |
| stdio MCP 子进程 | 读取全局凭证的工具，为每个用户连接启动独立受限进程 |
| 续期任务与登录锁 | 以用户连接为范围；A 的续期只更新 A 的记录 |
| 聊天、调用结果缓存、任务与报表 | 包含所属用户及授权数据范围，分别检查 |

MCP 本身不自动提供所有第三方服务的多用户凭证隔离。对只支持一份全局 token 或固定浏览器目录的工具，要改适配器或为用户分别创建实例。共享进程中不得通过改全局环境变量或全局 Cookie 切换用户。

## 请求链路

1. Windows 客户端带产品会话向 Arch 服务端发起请求。
2. 服务端验证会话，取得认证用户 ID 与工具权限。
3. 依据该用户 ID 查找用户拥有的连接和凭证，不接受模型或客户端指定任意用户 ID 来选择凭证。
4. 获取该连接对应的 MCP 会话／浏览器上下文，执行授权工具。
5. 对返回数据检查范围后，只把业务结果交给 AI 和客户端。

产品登录 token、MCP 服务连接 token、第三方服务 token 分别使用。凭证不进入提示词、聊天历史、工具结果或普通日志。MCP session ID 绑定认证用户，不能替代每次请求的鉴权。

## JSON 阶段存储计划

服务器保存工具定义和用户连接元数据。敏感字段采用认证加密，主密钥独立于 JSON 数据、权限仅服务账号可读；备份时分别管理密钥和密文。Windows 只接收连接名称、授权状态、所属第三方账号的允许展示信息及有效期，不返回已有凭证原文。

浏览器目录采用受控内部 ID 生成的路径，例如 `private/mcp-profiles/<user_id>/<connection_id>/`，不拼接用户提供的原始路径。服务器进程隔离和文件访问权限仍需落实，目录分开不等于完成权限隔离。

个人连接默认仅本人可调用。未来需要老板授权员工使用公司公共账号时，引入明确的共享连接和授权成员表；不会默认将任何员工的个人凭证变成公司公共凭证。

## 接入时验收

- A、B 同时连接同一工具时，每次执行都使用各自凭证及浏览器状态。
- B 提交 A 的连接 ID 时拒绝访问；角色为管理员也不自动导出个人密钥。
- A 重新登录、续期或断开连接不修改 B 的状态。
- 并发调用不会借用前一个请求的全局 Cookie、环境变量或客户端实例。
- 重启服务后仍正确恢复用户归属，日志中没有凭证值。

本设计结合当前应用架构制定。用户绑定的 MCP 会话和逐请求鉴权要求参见 [MCP 安全最佳实践：Session Hijacking](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices#session-hijacking)。
