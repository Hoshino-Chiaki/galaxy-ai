# 任务调度（实验）

该模块与 `youzan`、`feishu`、`guanjia` 同级，只负责 Galaxy 任务的日历规则、持久化、运行和工具入口。渠道业务继续通过现有 AI 与 galaxy-cli 执行。

- `rules.py`：带时区的单次、间隔、五段 Cron 规则，计算实际时间及接下来三次预览。
- `storage.py`：当前账号的原子文件存储。正式环境位置为 `private/accounts/<账号>/schedule/tasks.json`，同时保存任务及运行记录；不保存渠道密码或用户的桌面登录 token。
- `service.py`：定时扫描、原子认领、独立运行、取消及重启恢复。仅一个进程持有 worker 文件锁；同一任务不重叠，错过多个触发时只执行一次，不批量重放历史操作。重启时将此前运行标记为中断，已认领的业务不自动重试。
- `routes.py`：本人任务的查询、创建、时间修改和删除接口。`tools.py`：将 schedule 分类工具接到同一服务。
- CLI 注册模块：`galaxy-cli/src/galaxy_cli/tools/schedule/`，每个工具独立文件。

运行时重新读取创建者的权限和账号状态。为单次运行签发短期内部执行会话并在结束后注销，不依赖员工桌面是否开启；渠道凭证仍由当前员工的原 provider 提供。权限被撤销或账号安全版本变化时执行失败，不能沿用旧权限。创建者修改时间可重新确认任务授权。

每次运行使用新 conversation_id，结果、工具记录和附件保存在原有对话及文件服务。调度记录含运行状态和结果对话编号。若工具失败标记部分完成，若进程异常或授权失败标记未完成；状态成功表示 AI 本轮正常结束，实际业务完成情况仍须结合对话与工具回读核对。

结果保存在 Galaxy AI。用户明确要求微信投递时，可在任务 instruction 中安排调用 `clawbot.send` 发送文字与实际生成的文件，相应权限与微信绑定由该工具在执行时重新校验。发送失败会体现在工具结果与运行状态中，不能将创建任务或生成文件视为投递成功。无人值守执行不能等待选择框或上传，也不能创建、修改、删除其他调度。写操作继续遵守当前权限和渠道的既有边界，不会因定时执行提升权限。

客户端入口与 AI 同级，显示“实验”标签和范围说明。卡片修改时间跳转 AI 并关联服务器校验的任务 ID，聚焦空白输入框，等待用户发送新时间；更新只修改规则，不执行任务。删除要求当前 revision 防止覆盖并发编辑，正在运行的任务请求停止，历史结果对话保留。

依赖：croniter 6.2.4。权限迁移为 `backend/migrations/005_schedule.sql`。部署后无需给每个任务配置系统 cron，worker 在现有后端生命周期中运行，不新增本地服务。ClawBot 微信投递由渠道工具承担；其他渠道投递以已注册工具能力为准。
