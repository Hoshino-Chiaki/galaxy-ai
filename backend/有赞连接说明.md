# galaxy ai 有赞连接

管理员在 Windows 的「控制台 → 有赞」保存有赞账号和密码。界面自动读取已登录账号的店铺名称，在下拉框选择店铺即可，无需手填 ID；后台仍以有赞返回的 kdtId 标识店铺。

保存账号不会自动登录或刷新凭证。有有效 SID 时，进入页面会通过 HTTP 读取店铺名称；首次连接需点击「登录并读取店铺」。选择店铺后，可手动「刷新 SID 和 CRM」或「仅刷新 CRM CSRF」。未启用定时刷新或定时登录。

## 会话与 CRM 流程

1. 读取店铺列表使用 `https://www.youzan.com/v4/shop/getShopList.json`，仅携带当前连接的 SID，按页面参数分页获取名称和 ID。客户端只能选择当前账号已获取的店铺。
2. SID 刷新也优先通过该只读接口确认并复用已有登录；仅在确认缺少或失效时调用固定登录程序。网络故障、店铺权限错误和未知跳转不会触发重复登录。
3. CRM 先读取 `https://crm.youzan.com/crm/member/customer/manage`。需要店铺上下文时，访问正常的 `/v4/shop/enter-shop?kdtId=<所选店铺>&redirect=<固定CRM页面>`，然后读取最终页面的 `_global.csrf_token`。
4. 支持 CRM 正常迁移到 `/v4/scrm/customer/manage` 及 `store.youzan.com` 的同一路径。正常店铺选择或页面迁移跳转不再被误报成 SID 失效；真正跳回账号登录页才提示重新登录。
5. 跳转仅限明确允许的 HTTPS 主机、端口与路径，最多八步。未知站点、非 HTTPS、额外端口和循环跳转拒绝处理，不能把凭证发给任意地址。店铺进入参数始终由服务器已保存的选择构造。

2026-11-08 已用配置中的当前 SID 实测：取得 7 家店铺名称，通过进入店铺和 CRM → store 页面跳转取得 CSRF，无须再次提交账号密码或启动浏览器。

## 登录后台运行，不弹出窗口

仍复用已固定的 `session_research/youzan-login.cjs --managed-stdin`：真实 Chromium、指纹初始化、表单操作、原有滑块及密码登录流程保持共用。有效 SID 不启动该程序。确需登录时，在独立 Xvfb 显示里运行有界面模式的 Chromium，不连接 Arch 的交互桌面，不弹出可见窗口。

后台运行环境为 `backend/runtime/xvfb/usr/`，来自锁定 SHA-256 的 Arch 官方软件包，并未安装或修改系统软件包。来源见 `browser/background-runtime.lock.json`。迁移后初始化：

Xvfb 禁止 TCP 监听，子进程使用临时 X authority，并清除交互 `DISPLAY`、`WAYLAND_DISPLAY`，由运行器分配虚拟显示。固定 Playwright 和原坐标／轨迹依赖仍按 `session_research/youzan-login-runtime.json` 校验；原 `./youzan-login.sh` 命令行模式保持不变。

已验证当前用户服务约束下，Chromium 可在独立虚拟显示启动。后台模式的新账号密码登录仍受有赞页面及服务端验证结果约束；短信二次验证会明确返回未完成，不把滑块通过当成登录成功。

## 存储与权限

- 密码、SID、CSRF 在 `private/youzan.json` 中以现有 Fernet 密钥加密；店铺列表仅存名称和 ID。目录 0700、文件 0600，页面不回显凭证。
- 连接、店铺列表、任务和浏览器 profile 都按服务端认证用户及 workspace 隔离。客户端不能提供 owner、执行脚本、外部地址或 profile 路径。
- 浏览器 profile 在 `private/youzan-profiles/<连接UUID>/<凭证版本>/`，其浏览器会话数据库由目录权限保护，并非整个 profile 应用层加密。
- 更换账号／密码清除该连接的旧 SID、CSRF 和店铺列表。更换所选店铺保留 SID、清除旧 CSRF；选择本身不刷新凭证。
- 失败不覆盖以前成功取得的凭证；重新签发 SID 后清除旧 CSRF。每连接只运行一个任务，全局最多两个后台登录；可取消，重启不自动重试。
- 配置要求 `youzan:configure`，员工读写所有相关端点均被拒绝。AI 仍只可通过现有 `galaxy_cli` 调度已授权命令，本功能不增加 AI 读取凭证或登录工具。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v1/admin/youzan` | 连接、缓存的店铺名称、凭证状态及任务 |
| PUT | `/api/v1/admin/youzan` | 保存账号密码，空密码保留原密码；保留同账号所选店铺 |
| GET | `/api/v1/admin/youzan/shops` | 用已有 SID 更新店铺名称；不会启动登录 |
| PUT | `/api/v1/admin/youzan/shop` | 选择当前账号列表内的店铺 |
| POST | `/api/v1/admin/youzan/refresh` | `kind=sid`、`csrf`、`shops`，返回 202，后台执行本次手动任务 |
| POST | `/api/v1/admin/youzan/cancel` | 取消当前用户的任务 |

备份应保留 `private/youzan.json`、`private/ai-secret.key` 和所需浏览器 profile；仅备份密文无法恢复凭证。浏览器 Cookie 到期时间不保证有赞在此之前始终接受 SID。

## youzan 分类业务工具

手动刷新 CRM 时会从正常进入店铺的响应一并取得业务 `access_token` 等 Cookie，连同最终 CRM 来源加密保存为 `category_credentials`。SID 和 CSRF 继续使用原有独立密文字段；它们与该分类凭证都属于同一个用户、workspace 与所选店铺。页面不显示 token 原值。更换店铺、账号或重新签发 SID 会清除旧分类凭证。

客户查询工具 `galaxy-cli youzan customer-search` 自动使用这些信息。模型只能给出筛选条件，不能索取、提供或覆盖分类凭证。业务查询不会自动登录或刷新凭证；失效时要求在此控制台手动刷新。按分店名称筛选时使用已捕获并验证的 `youzan.shop.hq.store.search.afterdatapermission` 接口，只读取当前凭证有数据权限的分店名称及 ID。

工具输入、返回及示例见 [Galaxy CLI](../galaxy-cli/README.md)。


## 交互滑块与原编码器的连接

交互浏览器发出 `verification_input`、`kind=slider` 时，同时通过私有管道提供本轮挑战图片、组件几何及随机串。`YouzanLoginAdapter` 将这一类事件交给既有的 `session_research/encode_youzan_human_request.py`，不再等待客户端上传轨迹。编码器保留原加密载荷输出，额外返回同一计划对应的相对鼠标点序列；浏览器按该序列与松开等待时间操作，由页面原生 SDK 提交验证。

浏览器桥接位于 `backend/youzan/interactive-slider.cjs`。挑战按 token 及当前图片匹配，避免使用前一轮挑战的数据；图片、随机串和编码结果不通过公共管理接口返回。`send` 和 `code` 仍由当前登录账号的交互会话确认，验证码及旧有权限、取消逻辑不变。

验证覆盖：40 项后端回归、浏览器桥接模拟、真实图片编码及原生进程管道往返；服务器隔离副本实际触发编码器一次并继续到短信确认，测试在确认前停止，没有发送短信或覆盖正式连接。此修改不代表取消有赞要求的短信验证。
