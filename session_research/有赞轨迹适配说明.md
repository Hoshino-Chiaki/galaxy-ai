## 坐标不能直接照搬

保存的有赞登录前端把拼图块初始 left 设为 14 CSS 像素，之后：

`拼图块 left = 14 + 鼠标横向位移`（另受滑块行程上限约束）。

真实成功样本：最终 `cx=174`，鼠标累计横向增量为 160。适配器据此把 160 交给轨迹生成器，而不是把最终 left=174 当成移动距离。

图片定位沿用有赞项目使用的 ddddocr 1.5.6，但正确扣除该库裁掉的滑块透明边距，再按显示比例换算和取整。成功抓包中的识别结果可恢复为 `cx=174, cy=56, scale=0.5`。这证明此样本的坐标转换一致，不代表所有题图都能识别准确。

阿里云项目中的二次位移模型 `A_CDP/B_CDP`、阿里云 DOM 选择器和 YOLO 场景驱动没有套用到有赞。复用的是独立轨迹核心。

## 输出和时间轴

- 上游输出 `(dx, dy, dt_ms)`，适配为有赞 `slidingEvents`。
- 第一条保留组件内鼠标位置和绝对毫秒时间戳；后续各条为坐标与时间增量。
- 先对累计位置取整，再做相邻差分，避免逐点取整造成累计位移偏差。
- 按下、移动结束、松开使用同一时间轴；加密载荷中不混入 SDK 原本没有的鼠标松开字段，松开时间单独保存在计划元数据里。
- 调用端在声明的松开时刻到达后才能提交；轨迹中的时间不会凭空发生在提交请求之后。
- 加密仍调用已有有赞项目的 `utils.encrypt`。

## 使用

离线生成样例，不读取账号或联网：

```bash
investigation/youzan-slider/.venv/bin/python session_research/youzan_human_track.py --output session_research/youzan-human-track-demo.json
```

离线验证：

```bash
investigation/youzan-slider/.venv/bin/python -m unittest discover -s session_research -p test_youzan_human_track.py -v
```

HTTP 客户端的真实登录入口如下，会读取本地账号密码并提交登录；其浏览器环境与下面的真实浏览器入口不同：

```bash
investigation/youzan-slider/.venv/bin/python session_research/try-youzan-slider-login.py --login --precheck --track-engine human
```

本次通过的是独立真实浏览器测试入口：

```bash
node session_research/try-youzan-human-browser.cjs
```

现有隔离环境安装 ddddocr 1.5.6，它的包元数据声明 Python <3.13；当前环境使用 Python 3.14 忽略了该元数据限制，离线检查通过。部署时建议单独使用满足其版本声明的 Python 环境，勿直接换成返回中心坐标的新版本库。
