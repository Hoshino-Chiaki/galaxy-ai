# 固定登录程序

在项目根目录运行：

```bash
./youzan-login.sh
```

程序使用已验证的真实 Chromium 浏览器流程。先访问登录入口，依据服务器是否跳转至已登录区域判断会话是否有效；有效则保存状态后直接结束。需要重新登录时，读取根目录 `account_password.txt` 的第一行账号、第二行密码，初始化网站自己的浏览器指纹，提交页面原生前置行为，再使用适配轨迹完成滑块和密码登录。

只检查状态、不提交账号密码：

```bash
./youzan-login.sh --status
```

帮助：

```bash
./youzan-login.sh --help
```

## 本地文件

| 文件 | 用途 |
| --- | --- |
| `account_password.txt` | 账号与密码，本地读取，权限 0600 |
| `session_research/youzan-login.cjs` | 固定程序 |
| `session_research/youzan-login-result.json` | 最近一次结果，不含凭证原值 |
| `session_research/login-runs/*.json` | 每次运行的独立记录 |
| `session_research/youzan-human-browser-result.json` | 首次真实登录成功的原始脱敏记录，保留不覆盖 |
| `session_research/private/youzan-human-browser-profile/` | 复用浏览器目录，权限 0700 |
| `session_research/private/youzan-human-browser-state.json` | 浏览器状态，权限 0600 |
| `session_research/private/youzan-cookies.txt` | 可由 Python MozillaCookieJar 读取的有赞 Cookie，权限 0600 |

一份浏览器目录对应一个账号。复用时如 Cookie 中的手机号与账号文件不符，程序停止并返回账号不匹配，不自动退出另一个账号。

根目录包装脚本通过 `flock` 避免同时占用同一个浏览器目录。使用包装脚本启动。

## 结果和退出码

| 退出码 | 结果 |
| --- | --- |
| 0 | `session_reused` 或 `login_success_sid_saved`，确认已登录 |
| 10 | `--status` 检查发现需要登录 |
| 20 | 服务端要求短信再次验证 |
| 21 | 滑块结果未通过 |
| 22 | 缺少账号密码，或浏览器账号不匹配 |
| 23 | 浏览器、网络、适配器或依赖异常 |
| 24 | 已有另一个包装脚本实例占用锁 |
| 25 | 登录被拒绝或登录态无法确认 |

程序每次最多提交一份滑块结果和一次密码登录，不循环重试。遇到短信验证会返回明确结果，不自动发送短信。会话复用不会主动换发 sid；登录有效性和到期时间仍以服务器和浏览器 Cookie 为准。

- Playwright Core 固定为 1.63.0，安装在专用 `session_research/runtime/`，有 npm 锁文件，不再依赖 APK/桌面程序解包目录中的 Node 模块。
- 上游轨迹提交固定为 `3424e33a045cc66a5b6725aea43da41aca047930`。
- 启动时核对上游轨迹与有赞封装的源码 SHA-256，记录在 `youzan-login-runtime.json`。
- Python 使用现有独立环境 `investigation/youzan-slider/.venv/`；实际包版本记录在 `requirements-login.lock.txt`。ddddocr 固定 1.5.6，不能直接替换为返回中心坐标的新版本。
- 保留成功配置：`/usr/sbin/chromium`、真实窗口模式、1280×900。当前机器需要可用的图形显示；服务器的无桌面部署尚未在本轮验证。

## 验证依据

- 首次真实登录：新轨迹通过，密码登录 code=0，未要求短信，进入店铺列表并获得 sid。
- 固定版状态检查：返回 `session_reused`，没有提交密码或滑块。
- 默认入口重复运行通过：返回 `session_reused`，密码和滑块提交均为 0；sid 与运行前一致，CookieJar 可读取且与浏览器状态一致。

旧入口 `node session_research/try-youzan-human-browser.cjs` 保留为兼容入口；日常运行以根目录包装脚本为准。

## galaxy ai 服务端集成

现有登录流程增加 `--managed-stdin` 托管调用模式，由服务端通过私有 stdin 传入账号密码与用户隔离的浏览器目录，SID 通过私有 stdout 管道回收。原命令行方式保持不变，两个模式共用同一套已固定登录及滑块流程。托管模式不访问研究用的全局账号文件、Cookie 导出或报告文件。管理页面和存储说明见 [有赞连接说明](../backend/有赞连接说明.md)。
